Test Approach

Our test cases were systematically derived using four key testing principles
taught in class. We applied Boundary Value Analysis to test edge cases such as
empty input fields, zero items in cart, and empty search results. Equivalence
Partitioning was used to categorize inputs into valid and invalid classes, such
as testing valid versus invalid email formats and comparing empty versus
populated states. Decision Tables helped us test different combinations of
conditions, particularly for form submissions and navigation flows. Finally, we
applied Finite State Machine concepts to test state transitions in the cart and
authentication flows. Each component was analyzed to identify critical user
interactions and data flows, ensuring comprehensive coverage of both success
and failure scenarios while maintaining test uniqueness across all 20 unit
tests and 6 UI tests.

Experience Setting Up Automation and Running Test Cases

- Initial Setup: Configuring Jest and Playwright required creating separate
  configuration files (jest.frontend.config.js, jest.backend.config.js,
  playwright.config.js) and installing necessary dependencies. The separation
  of frontend and backend test configurations helped organize tests effectively.

- Mocking Challenges: React component testing required extensive mocking of
  React contexts (useAuth, useCart, useSearch) and external dependencies
  (axios, react-hot-toast). Understanding the mock hierarchy and ensuring
  proper mock setup in beforeEach blocks was crucial for test reliability.

- Debugging Test Failures: Two unit tests (Tests 12 and 14) correctly failed,
  detecting actual bugs in the application code (typo in error handling and
  missing cart functionality). This validated that our tests were effective at
  identifying real defects rather than just passing superficially.

- Playwright Configuration: Setting up Playwright UI tests required ensuring
  both backend (port 6060) and frontend (port 3000) servers were running. We
  encountered selector issues due to trailing spaces in placeholders, which
  taught us the importance of inspecting actual DOM elements rather than
  assuming placeholder text.

- Test Execution: Running npm test executes all 27 tests (20 new + 7 original),
  with clear pass/fail indicators. The npx playwright test command runs all 6
  UI tests, with detailed HTML reports available via npx playwright show-report.
  Test execution is fast and provides immediate feedback on code quality.
